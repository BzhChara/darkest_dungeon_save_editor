# Darkest Dungeon Save Editor v0.1.0-beta.3

This prerelease makes the native C# save codec the desktop default. Normal use no longer requires Java.

## Changes since v0.1.0-beta.2

- Reading, synchronization, map loading, edit previews and writes use one C# codec session. There is no automatic fallback to Java.
- JSON field names and string values use standard escaping, including the backslash-containing map ID reported in issue #3.
- Unchanged saves retain their original bytes. Edited saves preserve untouched native fields, duplicate occurrences and supported opaque payloads. Ambiguous duplicate-field edits and unsupported opaque edits fail with an error.
- The original JAR remains available for comparisons through `Start-JarReference.cmd` or `--codec=java`; the window identifies this reference mode. It requires Java 8 or newer on `PATH`.
- The native port and retained JAR preserve robojumper's original MIT copyright and permission notice.
- Item usage detection now recognizes Abbey and Tavern activity costs, Sanitarium treatment and quirk costs, and supported activity effects that add or remove currency.
- Resource warnings identify the affected item or loot-table IDs, source file and JSON location. Unknown Mod extensions continue to report uncertainty.

## Download and requirements

- Windows 10/11 x64 and a local Darkest Dungeon installation and save profile.
- Extract the complete `DarkestDungeonSaveEditor-v0.1.0-beta.3-win-x64.zip`, then run `DarkestDungeonSaveEditor.App.exe`.
- The .NET 8 runtime is included. Java is optional and used only by the JAR reference mode.
- Keep the `zh-CN`, `tools` and `licenses` folders. See `START-HERE.md` and verify the ZIP against `SHA256SUMS.txt`.

## Validation and compatibility

Local save copies and the issue #3 sample have been checked for native decode/edit/encode/readback, unchanged byte preservation and JAR comparison where supported. A dedicated modded campaign passed selected town and raid workflows in the game. Recruitment, hero trinket equipping and subsequent save/reload were also confirmed manually by the user.

Building item references were checked against a copy of the local campaign and its enabled content, with additional isolated town and raid regressions using both C# and JAR backends.

These checks do not establish compatibility with every Mod or save layout. The issue reporter's in-game environment remains to be verified. Scripted encounters, special ambush/teleport behavior and hidden/story maps retain the existing limitations. The optional MO2 replacement component must be rebuilt for this version and validated separately; do not reuse a beta.2 replacement DLL.

## Updating and licenses

Close the editor and extract this version into a new folder. Keep a separate save backup and confirm the selected profile before applying an edit. Existing preview, source-hash checks, closed-game checks and automatic backup rules remain in place.
