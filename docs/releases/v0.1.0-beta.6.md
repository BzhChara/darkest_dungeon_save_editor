# Darkest Dungeon Save Editor v0.1.0-beta.6

This prerelease adds current town-event editing, a native-style quest board and forced expedition-objective completion. It also clarifies Mod directory requirements and groups custom quest types by their effective objectives.

## Changes since v0.1.0-beta.5

### Town events

- Add an event when none is active, replace the current event, or initialize the same event again without advancing the week.
- Keep results already delivered outside the event, including heroes, stagecoach candidates, quests, items and settled progression. Clear unclaimed event-only recruitment and revival offers when replacing the event.
- Initialize the selected event's effects from active Base/DLC/Mod definitions. Later native recruitment, interaction and departure behavior remains game-managed.
- Show natural trigger requirements as reference information. Explicitly attached quests retain their own eligibility checks, with specific explanations for a skipped quest, such as an unfinished prerequisite or a completed non-repeatable quest.
- Keep trinket theft separate from recovery-quest generation. Use the quest board to add a recovery quest manually.
- Restrict event editing and hero generation to town. Event descriptions wrap, and exceptional quest notices use the shared warning area.

### Quest board

- Display the saved board with native map artwork, quest details, rewards, camping counts and region progression. Base, DLC and active Mod destinations are supported; destinations sharing coordinates use a region selector.
- Right-click a quest to replace or delete it; right-click an empty region to create one. Search and difficulty filtering use the effective game definitions.
- Group Mod types by their actual goals while retaining their native IDs, icons and difficulty. Unresolved types remain identifiable instead of being guessed from their names. Fix a picker crash affecting custom task records.
- Manual creation can bypass natural generation prerequisites. Correct initialization, save integrity and source checks still apply, and the game retains its entry and settlement rules.
- Preserve other board entries, campaign history and the current week. Persistent expeditions retain their saved maps; editing a board entry is not a map reset.
- Use a 50% embedded minimum with horizontal content centering and stable vertical framing. Full map shows the complete background. Controls, menus and logs follow the battle-map workflow.

### Expedition tools and loading

- Add **Force complete quest** for supported objectives: exploration, percentage-based room-battle clearance, monster targets, activation and gathering. The game performs the subsequent return and reward settlement. Skipped loot and independent Mod scripts are not simulated.
- Wave expeditions show an unsupported-map notice and retain **Force return to town**. The Old Road tutorial disables map editing and both force actions.
- Retain only the current ASCII Encounter Bridge identity. Retired directory/title aliases are not migrated or silently adopted. Current ownership, version, retention and encounter-index safeguards remain enforced.
- Require the selected game's local `mods` path when loading, including for vanilla saves; the folder may be empty. Workshop remains optional unless the saved Mod list needs it. **Auto discover** fills these fields only when clicked.
- Stop early when an enabled Mod cannot be found. Required-path errors, catalog diagnostics and synchronization failures are clearer in both languages. Chinese tabs now use Chinese-only headings.

### Optional packages

The matching MO2 replacement component includes these shared features and the explicit local-directory resolver hook. Its supported merge mapper remains `game_support_DarkestDungeon_20261016_004446`; MO2 provider paths still come from `mo2-compat.json`. The standalone Mod Order Converter is rebuilt with the same Core version; its interface and conversion rules are unchanged.

## Packages and updating

- **Editor:** extract `DarkestDungeonSaveEditor-v0.1.0-beta.6-win-x64.zip` into a new folder and run `DarkestDungeonSaveEditor.App.exe`.
- **Optional MO2 patch:** apply `DarkestDungeonSaveEditor-0.1.0-beta.6-MO2-patch.zip` to this beta.6 editor, following the included README. Keep your existing `mo2-compat.json`; do not reuse an older replacement DLL.
- **Standalone converter:** extract `DarkestDungeonModOrderConverter-0.1.0-beta.6-win-x64.zip` into its own folder and run `DarkestDungeonModOrderConverter.exe`.
- Check all downloads against `SHA256SUMS.txt`. The editor and converter include the .NET 8 runtime for Windows 10/11 x64; normal use does not require Java.
- Workshop files are under `editor/`, `optional-patches/` and `utilities/`. Copy the editor outside Workshop before applying the MO2 patch so Steam updates cannot replace it.

## Local data

Open `%LOCALAPPDATA%\DarkestDungeonSaveEditor` in File Explorer, normally `C:\Users\<your Windows user>\AppData\Local\DarkestDungeonSaveEditor`.

- `backups/` contains pre-write profile backups.
- `workspaces/` contains previews, decoded working copies and recovery evidence; the default MO2 cache is `workspaces/mo2-compat/`.
- `language.json` and `mod-order-language.json` store language preferences.

Retain backups and unresolved recovery evidence. Session logs and optional `mo2-compat.json` configuration are beside the standalone editor EXE. This application-data folder is separate from the actual game saves.

## Validation scope

Representative native-game acceptance covers event recruitment, revival, paid recruits and Mod event behavior; the five ordinary objective families; ordinary quest creation and settlement; Vermintide sewer quests; trinket recovery; Farmstead wave entry with force-town recovery; and Vvulf/Baron creation, entry, forced objective completion and native settlement. Contract checks cover initialization, native DSON round trips, source changes, backup/recovery, localization and UI state. These checks do not establish support for every Mod script or MO2 fork. Special ambush/teleport behavior and hidden/story maps retain their documented limitations. Java reference mode is retained, but this release's validation uses the C# backend.
