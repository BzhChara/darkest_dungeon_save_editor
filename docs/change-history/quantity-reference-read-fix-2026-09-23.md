# 物品引用读取完整性修复（2026-09-23）

按用户确认修复 [第三十九轮审核](historical-rule-audit-39-2026-09-23.md) 的一类低风险遗漏，基线为 `1215c8f84bcc19e45466bdd2570853aa4d41633a`。工件放在 `workspaces/quantity-reference-read-fix-20260923/`；旧审核报告和原探针证据不改写。

## 修改

- `QuantityItemReferenceAnalyzer.SourceDiscovery.cs` 和 `InternalModels.cs` 保留已选中的事件/掉落文件读取失败位置，避免略过失败后把后条当成确定来源。
- `QuantityItemReferenceAnalyzer.cs`、`RootParsing.cs`、`JsonRoots.cs` 将事件读取状态传至引用分析，复用 `OrderedDefinitionReadState`。完整首事件仍占位，包括空结果；未知前序之后的新 ID 只提供不确定证据。发布事件身份和证据前完整解析文件，避免中途字符串解码失败留下部分确定结果。
- `LootParsing.cs`、`LootTraversal.cs` 给每个掉落变体记录其前序读取是否完整。前序不完整时，物品引用及嵌套路径保留不确定性；前面的正常变体、条件区间、空表占位和独立配给用途继续有效。
- 新增 `QuantityReferenceReadContractTests.cs`，通过既有 `RunLootReferenceContractsAsync` 接入定向、目录及完整套件；规则更新在 `content-save-rules.md` 与 `resource-duplicate-semantics.md` 第 34 节。

这是目录引用状态及证据修复。没有增加旧存档兼容、迁移、Mod 改写、写入限制或新的同步定时器；数量保存、身份、堆叠、人物目录及战斗编号算法不变。当前界面仍不单独展示内部的已确认标签，分析不完整的物品继续默认显示。
