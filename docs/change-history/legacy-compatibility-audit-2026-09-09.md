## 原生证据与具体例子

完整字段边界、地址和适用范围已并入 [资源重复定义规则 §8](../resource-duplicate-semantics.md#8-hero-text-equipment-slots-camping-pools-and-item-references)。本地只读证据保存在 `workspaces/resource_semantics_live_20260908/`，该目录沿用实验产物忽略规则。

| 内容 | 关键原生入口/观察 |
| --- | --- |
| 人物记录与生成字段 | `0x1404C3860`；布尔调用 `0x14036C950` / `0x14036B0B0`，生成整数调用末字段 helper / `atoi` |
| 技能生成保证 | `0x1404C2D27` 使用 `0x14036C400`，随后调用同一个布尔转换 |
| HP 和概率百分比 | `0x14048695D` / `0x1404C401B` 调用 `0x14036C270`，数字转 float 后按紧跟的 `%` 缩放 |
| 普通和模式 Effect 列表 | `0x140481451`、`0x140481651`、`0x1404817A3`；普通列表和模式列表各自的追加分支 |
| 装备槽 | `0x1404C3956`–`0x1404C3A91`（武器）；`0x1404C3AEB`–`0x1404C3C1F`（护甲），按名称比较后复用/追加 |
| 扎营配置与分类 | `0x1404A4AF0`；原始数组长度比较 `0x1404A5F23`–`0x1404A5F3B` |
| 生成时使用哪条扎营技能 | `0x1405C7F76` 读取职业可用 ID，`0x1405C7FC0`–`0x1405C7FD4` 取得组内首条记录，`0x1405C7FE8` 读取分类 |
| 终止符 | `0x14028E1F5` / `0x14028E1F7`，原生 LineReader 遇 NUL 结束 |

例如护甲先声明 `worn_coat`，再声明 `replacement_armour_0`：它们是槽位 0 和 1，第二个名字中的数字不会把它移到槽位 0。之后重复 `worn_coat .hp 33`，更新的是第一个槽位。升级树仍然按该槽位记录的 `upgradeRequirementCode` 判断要求。

清单与路径也必须分层理解。清单列出 `monsters/作者分类/bandit_cutthroat_A.info.darkest`，意味着这个文件属于 Mod 的可提供资源；游戏根据这个怪物 ID 实际打开的是 `monsters/bandit_cutthroat/bandit_cutthroat_A/bandit_cutthroat_A.info.darkest`。旧物品引用分析在清单与同路径覆盖之后，直接读取前一种路径里的掉落引用，缺少 actor 的实际路径约束。这里的“旧扫描”不是无清单扫描。本轮也没有把所有资源都限制到人物/怪物的布局。

这里不是“先找标准路径，找不到再找分类目录”的回退机制。分类目录换成一个不重名的文件也不代表其内容会被采用：发现新 ID 后，依然根据那个 ID 构造定义路径。只有游戏本来会按相应范围枚举加载的资源（例如升级树文件），才应按该资源自己的枚举规则判断，不套 actor 的固定布局。

## 重点复核后保留的内容

| 现有规则 | 保留原因/边界 |
| --- | --- |
| 缺失 Mod 清单的官方生成流程、严格清单读取 | 用户明确选择的加载流程；本轮没有回退为无清单读取 |
| 同路径覆盖、DLC 挂载、原生文件槽顺序 | 文件来源选择与资源重复 ID 是不同阶段；物品/饰品 first、怪癖/Buff last、升级树逐 ID last 不能合成全局开关 |
| 无升级树技能的有界购买代码与同职业严格多数进程 | 购买代码有原生/实机证据；进程选择是明确标注的编辑器策略，保留基级降级与警告，不伪装成原生自动升级 |
| 怪癖排斥、进化目标链、条件 HP 风险验证 | 这些检查防止生成不可计算或危险的组合；文本来源修复不等于取消这些约束 |
| 物品缺引用/不完整扫描/存档残留三者区分 | 找不到引用不等于全局证明不能获得；已有数量项仍显示。饰品稀有度池仍不能套物品 ID 引用隐藏法 |
| 空遭遇占号但不能放置；未知体型、哈希与挂载顺序保护 | 删除空行再压缩计数会错号；有真实依据的空槽继续计数。不会把单条不可放置扩大为所有后续已证明编号都不可写 |
| Bridge 尾部校验、历史战斗归属、档案/副本身份、外部写入保护 | 这些是持久化和防误删保护，不是猜测游戏的加载补丁；旧成功写入日志的校验读取仍用于证明归属，不恢复旧 Bridge 文件格式 |
| 来源指纹、自动同步静默窗口、提交前重验、返回城镇事务 | 新解析结果继续走现有刷新与写前检查；本轮没有绕过这些机制 |
| 本地化键变体、保存项名称回退、LOC/LOC2、姓名池选择 | 属于显示策略或已有格式支持；不会把额外业务定义挂载进游戏 |

旧 [2026-09-06 兼容盘点](content-compatibility-audit-2026-09-06.md) 中“无清单读取”和“最优升级模板消歧”是历史状态，本轮已添加明确的失效说明，避免把它们当成当前规则恢复。
