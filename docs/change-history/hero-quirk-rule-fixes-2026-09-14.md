## 1. 上限来自活动 shared 规则

新增 `HeroClassCatalog.SharedRules.cs`，通过现有来源和文件覆盖解析器，读取当前实际有效的 `quirks_max_positive`、`quirks_max_negative`、`quirks_max_diseases`。`Models.cs` 中的 `HeroInitialQuirkLimits` 让目录、选择窗口、生成器和保存检查共享相同值。

- 离线查询为 `shared/` 下的 `.*rules.json`，包含子目录和原生未转义分隔符，不只读取单个 `shared/rules.json`。Mod 仍受清单限制；原版、模式、官方 DLC 仍使用对应物理查询。大小写和启用 DLC 前缀服从现有规则。
- 同路径先整文件覆盖，保持原生查询位置；不同有效文件按查询顺序逐字段更新。后面的文件没写某字段时保留此前状态，同文件的重复 JSON 属性取第一个精确名称。
- 原生默认值确实是 5 / 5 / 3。有效规则可将其提高、降低或置零。无覆盖字段时使用默认值，不把默认值当成固定上限。
- 只接受非负 32 位 JSON 整数。显式非法字段令对应类别“未知”；有效槽位的文件缺失、损坏或不可读时，三类均未知，后续明确有效字段可重新确定各自的值。缺失的清单条目仍保留覆盖位置，不能悄悄露出低优先级文件。
- 未知类别禁止添加，仍允许空白人物及其他已知类别。非法类型、负数等未定义输入没有被宣称为已完整模拟游戏行为。

例如：当前规则为正面 7、负面 7、疾病 5 时，可写入 6 正面、6 负面、4 疾病。若随后正面改为 1，再选择 2 个正面会被拒绝，界面显示的上限也随目录更新。变化进入人物目录指纹，使已准备预览失效；即使调用方拿旧人物配上新目录，保存准备仍会重新验证其实际怪癖列表。

`slot_size` 继续不参与这里的条数上限。游戏新增怪癖时的槽位消耗，与读档时的记录计数是两个不同消费者。没有把猩红诅咒等多槽定义折算成多条，也没有允许零槽定义绕过条数检查。

## 2. 进化判定使用具体字段与原生默认值

`HeroClassCatalog.QuirkDefinitions.cs` 删除 `ReadEvolutionSignature` 的任意前缀判断以及不再使用的 JSON 语义签名辅助代码。现在直接读取六个已知字段：持续时间上下限、目标、死亡标志、小镇推进变化量和使用物品阈值。

- `evolution_note` 等备注不参与判断。已知字段全部为零、无目标、死亡 false 时，与完全省略相同：普通怪癖，保存倒计时 0。
- `evolution_class_id: ""` 表示无目标，不再一律报“必须是非空字符串”。持续时间 12 / 12 且死亡 true 的定义，不论省略目标还是写空目标，都会保存倒计时 12。原生字符串遇 NUL 截断。
- 省略整数采用原生 0 默认值，例如只写最大值 12 并提供有效目标，范围为 0–12。
- 已声明字段必须是支持的正确类型。删除把 JSON `3.0` 自动当成原生整数 3 的兼容处理；原生读取检查整数类型位。范围反转、负值、非中立配置没有结果、真实目标缺失或下游无效仍受保护。原有精确 ID、首 JSON 属性和合法循环处理保留。
- 等价的备注／默认值变化会触发资源重新读取，但不再制造人物目录的语义变化，合法的已准备保存可以继续。
