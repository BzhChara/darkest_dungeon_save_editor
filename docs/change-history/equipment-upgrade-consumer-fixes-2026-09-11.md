## 最终行为

- `NativeDarkestReader.cs` 增加装备单字节读取入口，`HeroClassCatalog.InternalModels.cs` 用它读取 `upgradeRequirementCode`。最后一个精确字段生效，跳过空白后读取一个原始 UTF-8 字节；`alpha` 是 `a`，`"a"` 是双引号字节。省略字段保留原值，新条目默认 NUL，显式空字段清为 NUL。
- `HeroClassCatalog.Progression.cs` 删除“每档独立按等级匹配后取最大 rank”的旧算法，以及“所有高档必须有购买码”“所有树条目必须对应装备”的额外限制。新增 `HeroEquipmentProgression.cs`，按照实际购买记录顺序遍历装备，遇到首个未购买的非零要求就停止。后续符合人物等级的购买记录继续保留，并提示当前可达档位。免费高档可以在 0 级生效；未使用但合法的树条目不会使装备失效。
- `HeroSkillPurchaseTargets.cs` 为装备提供原生 63 字节购买目标；目录绑定和写入使用该目标。原始职业 ID、注册树 ID、通用 hash 不变。长完整树不再替代原生短目标；不同目标截断重合、hash 别名、装备和技能共用目标、NUL 或不完整 UTF-8 等情况明确限制生成。
- 原始装备元数据存入 `HeroClassDefinition` 的内部字段。生成时和 `SaveEditService.StagecoachHeroes.cs` 的提交预检会重算装备档位／护甲 HP，拒绝与购买计划不一致的预览。原始元数据也纳入已准备保存的目录指纹，避免两个不同定义恰好显示相同档位时漏掉变化。即使只保留 0 级回退，也按真实购买和免费档计算；无有效 HP 的结果不会伪造成 rank 0。指纹中的原始非有限 HP 使用命名 JSON 值，既保留差异，又不让无效的高档 HP 连带中断其他职业的保存。

例如：护甲 rank 0/1/2 的 HP 分别是 20/40/70；rank 1 要求购买 `a`（人物 3 级），rank 2 要求 `b`（人物 1 级）。生成 1 级人物时仍保留购买 `b`，但装备 rank 0、基础 HP 20；人物 3 级同时满足 `a/b` 时才使用 rank 2、基础 HP 70。

本轮另在实际 DSON 往返中确认转换器边界：单字节双引号和反斜杠解码时不做 JSON 转义，产生无效 JSON；NUL、控制字符及 DEL 等字节会解码为布尔值。新增 `DsonSaveCodec.CanRoundTripPurchaseCode`，由树解析、生成购买计划和 `StagecoachHeroSaveEditor.cs` 的直接 writer 共用。只允许一个非空白、可打印 ASCII 字符，排除双引号和反斜杠。不会把 `"a"` 偷换成 `a`，也没有修改第三方 JAR。该限制是现有编辑器转换器的能力边界，不是游戏禁止这些原生字节。

影响人物可生成等级、预览装备和初始 HP、购买记录以及保存前重校验。清单筛选、同路径优先级、升级树逐 ID 最后匹配、技能选择和隐式多数规则、怪癖计算公式、物品饰品、战斗／Bridge 与地图修改沿用现有行为。通用购买码检查覆盖装备和技能，但不改变普通数字／字母的含义。旧存档不自动修正。
