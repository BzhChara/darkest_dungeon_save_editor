# 清单统一加载实验：2026-09-08

用户确认：点击载入存档时，给当前档案勾选且能定位的 Mod 补齐缺少的 `modfiles.txt`；所有 Mod 资源只走清单，移除无清单扫描。所有类型的同路径文件统一按 Mod 顺序覆盖，上方优先；不同文件重复 ID 保留已验证的游戏规则。

## 实现

- `ModManifestPreparationService` 在显式加载的活动来源解析之后、目录和指纹读取之前执行。只处理选中且缺清单的 local/workshop 来源，准备全部输出后再逐一安装。已有清单、禁用 Mod、真实资源文件和存档不改写。
- `OfficialModManifestGenerator` 仅运行已核对 SHA-256 的游戏官方工具，模式固定为 `dont_submit`。临时目录包含工具依赖、包装项目、原 Mod 副本与同路径原版文件；包装层避免官方编译步骤改写原地图或本地化。官方输出去掉包装前缀，核对路径、大小和枚举结果后交给准备服务。
- 与原版相同文件按官方工具规则省略。这可能使其他 Mod 的同路径修改重新生效，是本次用户明确选择的策略，不宣称与原来无清单加载完全等价。
- 生成前后和安装前检查游戏未运行、档案配置与源文件未变化；切换档案或关闭窗口会取消准备。临时子进程退出/超时/取消均收尾，抑制原生崩溃弹窗。
- 主窗口保存加载任务；关闭时先取消并等待完整任务结束，再允许窗口真正关闭。重复关闭不会绕过等待，避免 WPF 提前退出而中断官方工具的收尾。
- 每份清单以不覆盖方式安装，保存新增路径与哈希的 JSON 记录。如果安装中断，之前已成功新增的清单保留并报告；再次载入只处理仍缺少的清单。回退编辑器代码不会删除 Mod 目录中的这些文件。
- 物品、饰品、存储容量、人物/怪癖及依赖、战斗/怪物、奇物、引用关系和名称目录统一使用清单。原版、游戏模式及启用 DLC 的物理入口保留。完整磁盘盘点只用于诊断。
- 文件覆盖统一到 `NativeContentFileResolver`；未验证的语义规则仍按原逻辑处理。物品/饰品首次匹配、怪癖最后匹配、标准人物路径、场景与存档结构、怪癖互斥/进化及写入事务均保留。
- 人物皮肤候选中的 Mod 目录要求有清单列出且实际存在的 PNG，不再仅凭空目录或清单外图片增加可选色号。保留从 A 起连续色号和已有下层人物提供者的外观继承；图片存在性变化参与刷新指纹，图片像素内容不参与昂贵的逐次哈希。

## 边界

当前只支持已核对的官方上传工具版本；临时目录须为 ASCII 路径，链接/重解析点 Mod 不自动生成。清单输出为空或不能验证时停止。已有清单不因新增资源自动重建，资源更新须由作者维护清单；读取已列文件的内容变化仍会触发自动刷新。

自动同步、预览和写入前检查不新增清单。新选中 Mod 缺清单时应关闭游戏后点击载入。未解决来源歧义、未知语义重复 ID 和 DLC 编号等既有保护不因统一清单取消。
