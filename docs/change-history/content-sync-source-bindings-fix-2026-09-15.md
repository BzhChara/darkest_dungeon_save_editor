# 来源映射写入保护与空闲同步修复

日期：2026-09-15；基线：`13a7c7f`。对应[第二十九轮审核](source-binding-guard-audit-2026-09-15.md)及用户反馈“什么都不干也频繁同步，重置期间无法操作”。

## 修改

- `MainWindow.ProfileSync.cs`：10 秒资源轮询和窗口激活先做后台检查，无变化时保留预览、按钮、输入、状态和日志；确认变化后独占维护与界面发布。真实存档通知、不完整存档仍暂停旧数据写入。
- `MainWindow.State.cs`：记录操作代次，丢弃检查期间已经开始并结束的用户操作之前取得的结果，避免只看当前 busy 状态造成竞态。
- `ProfileCatalogSnapshotReader.cs`：复用未变化的已解码游戏配置；空闲轮询不重写临时存档；保留完整哈希、定义内容更新和双目录缓存检查。
- `ActiveContentResolver.cs`、`Models.cs` 与各写入保护：保存实际解析根目录和配置，在预览、提交及战斗维护时重新确认来源映射。覆盖本地标题改名、同名冲突、跨根目录映射变化，以及已启用的模式/DLC/Workshop 资源后来才安装的情况。
- 战斗维护区分“等待游戏退出”与“等待其他持久副本”，前者在退出后重试；无变化时不反复打断界面。
- 独立审查指出的两个边界已补充实现与测试：解码位置单独避开仍被发布快照使用的游戏缓存；暂时失败的战斗维护保留待重试状态，后台只读检查不会写存档、已安装 Bridge 或恢复回执，确认存在可继续执行的工作后才进入独占维护。中断恢复完成也会明确触发快照刷新。
- 补充检查“可读但禁止替换”的占用：只读检查在返回待写入状态前，用现有文件的 Windows `DELETE` 访问权限确认替换共享条件，不改文件内容。该检查同时用于普通维护和中断恢复，允许显式共享替换的读取句柄。

保留原有同路径覆盖、重复 ID、怪物编号、地图清理范围及保存回滚规则。没有修改实际档案、用户 Mod 或 Steam 状态，没有提交本轮代码。

开发期间发现并修正了测试初始化问题：首次 WPF 测试写入默认 AppData 工作目录，被沙箱拒绝；现使用明确的项目内测试工作目录。测试直接加载应用主题，避免触发启动窗口。新增中断记录用例最初使用了大写哈希，已改为产品实际写出的格式。一次默认并行构建返回退出码 1，但没有编译错误诊断；最终按仓库已有的单线程构建方式完成全解决方案构建。
