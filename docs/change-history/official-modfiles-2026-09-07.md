## 官方目录说明与编辑器读取的区别

检索确认有 Red Hook 的[官方 Mod 指南](https://steamcommunity.com/sharedfiles/filedetails/?id=819597757&l=english)，页面标注最后更新于 2017-07-10。指南要求沿用游戏的相对目录层级，并说明同路径 Mod 覆盖优先级；它没有给出 `modfiles.txt` 的完整处理规范。本轮没有找到覆盖当前版本所有资源加载器的官方目录、递归与解析规则表。

结合本机工具、游戏原生函数和现有编辑器代码，可以明确区分：

| 阶段 | 已验证行为 | 不能由此推出的结论 |
| --- | --- | --- |
| 官方工具生成清单 | 枚举文件，与基础 data 同路径文件按长度和字节比较，输出改变或新增文件的记录 | 不会据此识别作者遗留的旧版本；README、源码和快捷方式也可能被列入 |
| 游戏查找文件 | 根据当前挂载、清单或物理目录设备，以及调用方请求的路径和模式查找提供方 | 不是运行时逐一与原版比较内容后再加载；清单记录不证明某资源已经被请求或完整初始化 |
| 编辑器解析目录 | `ContentFileDiscovery` 按类别目录与后缀发现候选，清单存在时限制候选；`NativeContentFileResolver` 等处理来源和有效定义 | 尚未完整复现全部资源、全部 DLC 顺序与全部运行状态；不能宣称已经完美识别游戏使用的所有资源 |

怪物是目录结构之外还需查找规则的实际例子：已经验证的游戏流程先发现 ID，再按该 ID 构造标准 info/art 路径。扫描到 `monsters/游荡/bulrush/bulrush_E/bulrush_E.info.darkest`，不能直接认定这里的内容就是游戏采用的定义；正常查找的相对路径为 `monsters/bulrush/bulrush_E/bulrush_E.info.darkest`，并独立查找对应 art 文件。现编辑器已在 `BattleEncounterCatalog.SourceDiscovery.cs` 中按支持的 ID 构造标准路径。

因此官方结构可以作为统一发现规则的依据；有效定义仍需结合实际挂载优先级、同 ID 处理、标准路径查找与各资源的引用规则。目录结构、清单记录和资源可用于当前战斗，是不同的判断。官方工具也不具备可靠的“旧文件/未使用文件清理”能力。

相关原生证据见[运行时挂载研究](runtime-mount-research-2026-09-07.md)和[上传工具隔离研究](uploader-manifest-research-2026-09-07.md)。官方指南与本机研究结论在本记录中分开注明，不把研究推断归为官方承诺。
