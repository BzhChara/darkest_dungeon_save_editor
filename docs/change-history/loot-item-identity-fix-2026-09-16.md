# 掉落引用身份修复（2026-09-16）

## 修复内容

修复[第三十四轮审核](historical-rule-audit-34-2026-09-16.md)确认的误隐藏问题：游戏能够通过 NUL 结束、63 字节缓冲区或哈希别名识别的掉落引用，现在能对应到编辑器中实际加载的物品定义。

- `QuantityItemReferenceAnalyzer.LootParsing.cs`：条目类别按 C 字符串哈希识别；物品类型和 ID 按各自最多 63 个 UTF-8 字节计算引用哈希，复用现有掉落字符串处理，不先把截断字节解码为替代字符。
- `QuantityItemReferenceAnalyzer.InternalModels.cs`：增加掉落专用的定义哈希索引，按定义完整 C 字符串的哈希查找。普通直接引用和货币引用保持各自入口。
- `QuantityItemReferenceAnalyzer.LootTraversal.cs`：分别报告物品定义冲突和权重不确定；两者同时存在时保留两种原因。
- `LootItemIdentityContractTests.cs` 及 `LootReferenceContractTests.cs`：新增正式回归并接入 `--loot-references` 和完整套件。
- `docs/content-save-rules.md`、`docs/resource-duplicate-semantics.md` 第 29 节、测试说明及本记录：说明消费者边界、原生证据和验证结果。

匹配到引用别名后，展示和保存仍使用所选定义的原始身份。例如掉落引用 `BE` 找到唯一的 `Az` 定义，保存写入 `Az`。多个定义存在真实提供者或哈希歧义时，掉落引用只贡献不确定证据，原有只读保护保留；独立确认引用及官方来源按原规则处理。

这次影响引用标签、默认隐藏筛选及资源重新加载后的目录结果。没有修改 Mod 优先级、无清单处理、同 ID 定义的数值选择、保存格式、数量分配算法、同步周期、战斗编号或 Bridge 自动维护。没有新增依赖、迁移或旧版本兼容。
