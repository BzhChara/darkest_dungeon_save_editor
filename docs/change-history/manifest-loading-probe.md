# `modfiles.txt` 最小加载对照测试

2026-09-06 已使用 Computer Use 完成本地英雄覆盖 A/B 实测：清单漏列的强盗覆盖不再生效，保留条目的十字军覆盖继续生效。完整结果、适用边界和收尾状态见 [实测记录](manifest-loading-result-2026-09-06.md)。以下保留可复现步骤，不代表所有文件类型均已验证。

## 目的与范围

验证当前游戏版本对**本地 Mod 的现有英雄 `.info.darkest` 覆盖文件**，是否读取“文件存在，但没有列入 `modfiles.txt`”的定义。测试结果用于决定后续扫描规则，不提前认定引擎行为。

只比较同一 Mod 的 A、B 两种清单；不是安装两个 Mod。两组英雄文件、项目标题和 `project.xml` 逐字节相同，唯一差异是 B 的清单少列一份强盗定义。B 中这份定义仍然存在，文件内容没有恢复成原版。

| 对象 | 定义变化（所有武器等级） | A 清单 | B 清单 | 用途 |
| --- | --- | --- | --- | --- |
| 强盗 `highwayman` | 武器速度 +50 | 列入 | 不列入 | 检查清单外文件是否加载 |
| 十字军 `crusader` | 武器速度 +20 | 列入 | 列入 | 确认两次测试中 Mod 都在生效 |

不修改生命、技能、怪癖、升级标识或人物生成规则。游戏界面显示的是总速度，可能包含怪癖等加成，所以主要记录 **A 与 B 的差值**，不要求显示值刚好是 55 或 21。

## 安全边界

- 使用一个**新建的临时测试档案**，只启用本测试 Mod。不要用于现有 `profile_0`、`profile_1`、`profile_3`，也不要覆盖已有档案。
- 不要为了腾出档案位置删除现有存档；如果没有空位，先停止并告知，改用经确认的隔离方案。
- 生成脚本只读取游戏本体的两份英雄定义，输出到编辑器项目 `workspaces/manifest_loading_probe/` 下的新目录；不安装、启用 Mod，不读取或改写存档，不运行上传工具。
- 游戏内测试会正常保存临时档案；“脚本不改存档”不等于“游戏测试不会保存”。
- 新建临时战役也不能隔离游戏自动维护的共享数据：本次启动期间 `profile_9` 的聚合哈希变化，马戏团与教程文件时间更新。以后同类测试须把这类后台写入纳入快照范围；不要把“未进入原战役”表述为“整个用户数据目录完全未变”。
- 每次安装、切换清单或清理测试 Mod 文件前，必须**完全退出游戏进程**。退到游戏主菜单不算退出；Mod 的启用/停用则在档案选择界面操作，不在已加载的档案中切换。
- 不要把 A、B 同时安装为两个 Mod，不要运行 Steam 上传工具或重建清单。

## 生成测试包

在编辑器项目根目录，用 PowerShell 7.1 或更高版本执行（游戏路径按实际位置填写）：

```powershell
./tools/PrepareManifestLoadingProbe.ps1 -GameDirectory 'E:/Steam/steamapps/common/DarkestDungeon'
```

命令返回本次 `PackageDirectory`。打开该目录，结构如下：

```text
README.zh-CN.md
evidence.json
A-listed/DDSE_Manifest_Loading_Probe/
  project.xml
  modfiles.txt
  heroes/crusader/crusader.info.darkest
  heroes/highwayman/highwayman.info.darkest
B-unlisted/DDSE_Manifest_Loading_Probe/
  （相同结构，只有 modfiles.txt 内容不同）
```

`evidence.json` 记录本体来源哈希、生成文件哈希、每级武器速度变化和预期安装位置。生成的游戏文件位于 Git 忽略目录，不提交到仓库。

## 游戏内步骤

### 1. 安装 A，确认对照成立

1. 游戏完全关闭后，将 `A-listed` 里面的整个 `DDSE_Manifest_Loading_Probe` 文件夹复制到游戏的 `mods` 目录。最终应为 `mods/DDSE_Manifest_Loading_Probe/project.xml`，不能多套一层 `A-listed`。
2. 如果目标处已经存在同名文件夹，不要直接合并覆盖，先告知以核对旧测试包。
3. 在一个新临时档案上，只启用 **DDSE Manifest Loading Probe**；无需开启其他 Mod。不要改变正式档案的 Mod 配置。
4. 进入临时档案，查看初始强盗与十字军的人物面板，记录速度或截图。无需战斗、移动或过周。记录档案位置、游戏版本和两人的武器等级；后续保持不变。
5. 强盗和十字军都应有明显的速度增加。如果任何一个仍是普通低速数值，先停止测试，检查安装层级、启用状态和定义是否被其他内容覆盖。
6. 正常保存并完全退出游戏。

### 2. 只切换为 B 的清单

1. 从 `B-unlisted/DDSE_Manifest_Loading_Probe/` 复制**仅 `modfiles.txt`**，替换刚安装的测试 Mod 内同名文件。不要替换、删除英雄定义，不要更改 Mod 文件夹或标题。
2. 打开安装目录中的清单确认：仍有 `heroes/crusader/crusader.info.darkest`，没有 `heroes/highwayman/highwayman.info.darkest`。强盗文件本身应仍在 `heroes/highwayman/` 中。
3. 重新启动游戏，确认测试 Mod 仍启用。进入**同一个临时档案**，在相同位置查看同两名角色，记录速度。不要升级、换装、战斗、改变怪癖或过周。
4. 保存退出后保留安装目录与清单，供只读复核。由 Computer Use 操作时直接保存临时档案路径、下表结果及两组人物面板截图；用户自行测试时也可提供相同证据。

| 阶段 | 强盗总速度 | 十字军总速度 |
| --- | --- | --- |
| A：两份定义都列入清单 | 待填 | 待填 |
| B：只漏列强盗定义 | 待填 | 待填 |

### 3. 结果判断

| 观察 | 含义 |
| --- | --- |
| 十字军仍保留 +20，强盗比 A 低 50 | 支持此本地英雄覆盖文件受清单约束 |
| 十字军和强盗都保持 A 的加成 | 支持此本地英雄覆盖文件仍可在清单外加载；需复核实际清单与启用状态后确认 |
| 十字军也失去加成、变化不是预期差值，或 A 本身未生效 | 对照不成立，不能据此修改扫描规则 |

若结果有歧义，下一步才安排在这个临时档案上停用测试 Mod、冷启动并检查两项加成是否都消失，以排除未退出、缓存或其他来源干扰。无需一开始增加这一步。

单次结果不能直接推广为“所有工坊 Mod、所有类型都遵循同一规则”。新增英雄 ID、怪物定义、JSON、遭遇表、DLC 条件目录、图片和编译本地化仍属于不同证据范围。不能仅凭本测试认定此前所有清单外文件都可补读或都应排除。

## 测试结束与回退

测试完成后，可在档案选择界面打开临时档案的 Mod 配置并停用测试 Mod，然后完全退出游戏。不要将其留在正式档案启用列表中。如果之后需要清理，目标只限本次安装的 `mods/DDSE_Manifest_Loading_Probe`，不要删除 `mods` 根目录或任何原有 Mod。编辑器不会替你删除文件。

本轮没有增加技能或物品 ID，不需要保留测试 Mod 作为存档依赖；但临时档案应继续留作测试用途，不作为正式进度使用。
