# 物品保存身份与饰品次数修复（2026-09-14）

范围是用户确认修复的[第二十四轮审核两项问题](trinket-counter-and-save-identity-audit-2026-09-14.md)，基线为 `b25205e`。没有提交本轮代码，没有修改真实档案、活动 Mod 或 Steam 配置，也没有启动游戏。

## 与之前长 ID 修复的关系

之前确实修复过 63 字节边界：`c624056` 处理人物技能购买目标，`29e0a88` 处理背包容量配置的类型名，人物装备与地图资源也有各自消费者的边界处理。这些不是普通物品和饰品存档 `id/type` 的保存入口。后者仍保留早期完整字符串写入；`d55a15f` 修复精确大小写／空白身份、`b25205e` 集中修复资源大小写时，也没有补上这一保存限制。因此属于之前覆盖不完整，不是已有物品保存长度检查被回退。

## 实际修改

- `NativeInventoryIdentity.cs` 和 `Models.cs`：依据游戏物品及钱包恢复缓冲，统一验证**实际保存字段**的 63 个 UTF-8 字节上限、NUL 和不可编码字符串。目录完整保留原 ID，计算 `SaveIdentityIssue`，不截短替换。钱包只验证持久化 `type`；传家宝把 ID 映射到该字段，金币定义里未使用的 ID 不作为钱包保存字段检查。
- `TrinketCatalog.cs`、`QuantityItemCatalog.Definitions.cs`：输出身份限制诊断；原生哈希冲突处理考虑 C 字符串的 NUL 终止。长、短且哈希不同的定义仍独立存在，不伪装成来源覆盖冲突。
- 三个数量／饰品存档编辑器及两个保存服务：直接修改、预览与提交校验覆盖相同的保存身份限制。仅读取／统计存档不截断原值；保存独有物品也不能绕过验证。
- `MainWindow.State.cs`：选中无法原样保存的身份时显示具体原因并禁用预览；重新选择正常项仍走原流程。
- `TrinketCatalog.cs` 和 `TrinketSaveEditor.cs`：删除“次数必须为正整数”的读取器及 `UnsupportedStateFields` 旧阻断。首个 JSON 成员是 Int32 时保留其值；否则保留原生默认状态。新实例只写出非负次数，包含零；负值／缺省不伪造成零，后续重复字段和同 ID 条目不补救首项。
- 正式测试修正了旧的零次不可用预期，增加 `InventoryPersistenceContractTests.cs`；现行规则写入 `content-save-rules.md` 和 `resource-duplicate-semantics.md`。历史审核报告保留当时的缺陷证据。

同路径覆盖、重复资源顺序、正常 ID 的大小写／空白、堆叠上限、饰品总容量、定义数量上限提示及内容变更保护保持原有规则。未加入存档迁移或旧候选兼容。

## 补充原生证据

仍以 x64 build 27890、EXE SHA-256 `35e5a653279992564809ff8406febd5a02a7d6961044781b1296b38a7096f59b` 为准。

1. 钱包恢复在 `0x14055BD53–0x14055BD6A` 读取 `type`，目标大小 `0x40`，随后对读入缓冲计算哈希。与普通物品的 63 字节边界一致。
2. 饰品可选计数检查 `0x400` 位。沿资源 JSON 解析链核实数值构造：Int32 负数 `0x1606`、非负数 `0x3E06`；宽整数按 Int32 边界置位；小数／指数值为 `0x4206`。因此此次不仅允许零和 null，还明确覆盖负数、Int32 两端、溢出整数、小数及指数形式。
3. 原生保存仅输出大于 `-1` 的次数；缺少实例次数时从定义回填。省略负数与显式零不同。
