# 人物升级树按最后匹配定义解析：2026-09-08

用户要求将已实测的升级树读取规则接入编辑器。依据为 [古董商实机实验](antiquarian-upgrade-probe-2026-09-08.md) 中的游戏结果及 build 27890 原生加载、查找函数。

## 修改

- `HeroClassCatalog.Progression.cs` 删除 `SelectCompatibleHeroUpgrade` 整文件评分与选择，改为按有效文件顺序及文件内声明顺序，逐个精确树 ID 保留最后定义。不同文件分别提供的树可以同时供同一人物使用；重复树整体替换，不拼接旧 requirement。
- `HeroClassCatalog.SourceDiscovery.cs` 读取 `upgrades` 下全部层级的升级 JSON，继续遵守 Mod 清单和已启用 DLC 限制。文件名不再作为职业 ID；同路径覆盖与原有位置顺序仍由 `NativeContentFileResolver` 处理。
- `HeroClassCatalog.cs`、`HeroDefinitions.cs`、`InternalModels.cs`、`DefinitionResolution.cs` 接入按树目录，删除旧整文件候选、签名及兼容评分模型。人物绑定自己的武器、护甲和已识别战斗技能 ID，不把其他人物或未引用树写进个人购买记录。
- `Models.cs` 为每棵人物升级树保存来源、源文件和不能使用的原因。`StagecoachHeroCandidateFactory.Progression.cs` 在生成及提交前购买计划复查中拒绝有明确错误的生效树，防止被误当成缺失树并套用隐式技能兼容。全局游戏哈希冲突按既有安全策略阻止受影响人物；其他人物仍可生成。
- `HeroUpgradeTreeContractTests.cs` 补充读取至候选、购买计划和 DSON 编解码的回归，现有目录断言不再要求整文件冲突或兼容评分。

## 行为范围

影响人物目录刷新、可生成等级预检、装备等级与 HP 推导、技能购买代码、驿站人物预览及提交前校验。既有内容指纹已递归包含 `upgrades`，提交前仍会重读人物目录并比较指纹。

树完全缺失时原有隐式技能购买兼容保持不变。怪物、战斗 Bridge、背包和饰品业务未修改；编辑器没有新增金币价格或公会付费购买功能。本轮不改真实档案、原 Mod 或游戏配置，也不重新安装实验 Mod。
