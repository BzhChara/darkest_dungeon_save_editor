# 物品、饰品重复定义的游戏实测：2026-09-08

用户要求像古董商技能树实验一样，在当前 `profile_1` 中实际验证物品与饰品的重复 ID 规则，并确认人物、怪物的各类属性是否都采用最后匹配项。本轮完成两组游戏内对照、清理后第三次入档恢复检查及本地存档核验，没有修改编辑器产品代码。

## 结论与对照

在本机 Windows x64 build 27890 中，两组结果支持当前规则：先解析同路径文件覆盖，再在实际加载的资源表中查找；数量物品取首个 `(type,id)` 匹配项，饰品取首个 ID 匹配项。这里的“首个”指资源表顺序，不能直接替换为“Mod 列表最上面”。

实验对象为食物 `(provision, "")` 和存档中已有的 `EosScourge_Trinket4`（炽热的灵魂硬币）。临时 Mod `DDSE Item Trinket Rule Probe` 在原有 Mod 列表上方启用，保留其他 Mod 相对顺序。

| 对照 | 食物游戏内结果 | 饰品游戏内结果 |
| --- | --- | --- |
| 较早条目 A 与较晚条目 B 同时存在 | 售价 1373；购买 5 个分成 3＋2 格 | 仅显示 +11% 最大生命，没有合并 B 的 +7 速度 |
| 移除较早的重复条目，保留 B | 售价 2467；购买 8 个分成 7＋1 格 | 显示 +7 速度 |

第二组确认较晚的文件本身能被游戏读取，排除了“B 格式无效或文件没有加载”导致第一组看起来像首次匹配的解释。两组均从 Steam 启动并实际进入同一档案；通过点击跳过片头。未进入副本、购买升级或装备/出售测试饰品。食物在补给页买入，返回任务选择后全额退款，金币回到 357,860。

## 文件与运行时证据

- A 食物覆盖 `inventory/base.supply.inventory.items.darkest`，复制当前有效 Workshop `840387268` 的文件，只改食物行；其余物品行保留。B 位于新增路径 `inventory/zz_ddse_rule_probe.inventory.items.darkest`。
- A 饰品覆盖 `trinkets/EosScourge.entries.trinkets.json`，复制当前有效 Workshop `3470633966` 的文件，只替换目标条目；B 位于新增路径 `trinkets/zz_ddse_rule_probe.entries.trinkets.json`。两种属性使用本次新增且 ID 不重复的 buff，避免把 buff 库自身的重复规则混入测试。
- 第一组的只读进程捕获发现三条食物记录，序号/堆叠上限分别为 `26/3`、`37/12`、`264/7`。额外的 12 来自原版 `inventory/mode.supply.inventory.items.darkest`。同名 Workshop 文件未列入其清单，不能因物理存在就当作有效覆盖。
- 第二组同时从临时覆盖文件中移除 base.supply 和 mode.supply 的食物行；mode.supply 用注释文件覆盖。此后捕获的食物只剩序号 `262`、堆叠上限 `7`。
- 第一组目标饰品在原生表中的序号为 `928` 和 `1247`；第二组仅剩序号 `1246`。运行时采集仅申请查询和读取权限，没有注入、挂钩或内存写入。
- 编辑器对两组读取的食物堆叠分别为 3、7，来源分别为上述较早、较晚文件；饰品价格元数据分别为 11110、22220，来源选择一致。饰品价格没有通过游戏出售操作验证，不能把这些编辑器价格写作游戏内实测售价。

只读反汇编再次核对：物品匹配代码块 `0x1404F173E–0x1404F1771` 比较类型和 ID 哈希，首次同时匹配就退出循环；饰品 `0x1404F6491–0x1404F64B9` 首次 ID 哈希匹配后保留该条目并退出查找。适用 EXE SHA-256：`35E5A653279992564809FF8406FEBD5A02A7D6961044781B1296B38A7096F59B`。这些是首选基址地址，捕获脚本按实际模块基址换算。

## 人物与怪物不能统一为“同 ID 最后一条”

| 资源 | 已确认的处理层次及边界 |
| --- | --- |
| 人物、怪物的基础定义 | 发现职业/怪物 ID 后构造标准路径，再打开有效的 info、art 文件；人物还会读取存在的 override。各路径分别按文件提供方优先级解析，不是搜遍任意文件后对整个人物取最后一个对象。 |
| 人物战斗技能数值 | info 中按技能 ID 和等级组织；古董商 `kris_stab` 同一 ID 存在 level 0–4 五条记录。这五个等级不能按 ID 压成最后一条。重复同 ID、同等级记录的全部处理细节本轮未另做实测。 |
| 人物升级树 | 已在前一轮结合原生代码和公会实测确认按树 ID 取最后匹配树。树决定购买价格和门槛，不代表技能本体的属性也采用同一查找方式。详见古董商实验记录。 |
| 怪物技能、AI 和机制 | 怪物 info 包含 skill、monster_brain、death_class 等不同声明，技能还引用 effects，相关 buff/AI 库各有加载及查询过程。本轮未把这些类别的全部重复语义逐项验证，不能宣称全部已确认 last-match。 |
| 怪物战斗组合 | 按地区、难度、mash 类型，将有效文件中的遭遇行有序加入对应表并形成运行时索引；地图保存该类型/索引。这是位置编号，不是以怪物 ID 去重取最后一条。 |

原生路径依据为 `0x1404C3230` 和 `0x1404CD210`：人物构造 `heroes/<id>/<id>.info.darkest`、`.art.darkest`、`.override.darkest`；怪物构造 `monsters/<family>/<id>/<id>.info.darkest`、`.art.darkest`。同一行中重复标量字段（例如此前核对的 `.size`）的最后字段规则，又是另一层解析行为，不能当作所有资源对象的统一覆盖规则。

人物升级树当前的整文件兼容选择仍需后续单独接入按树解析，本轮未修改它。物品引用分析、存档写入、Bridge 和战斗地图业务也未修改。
