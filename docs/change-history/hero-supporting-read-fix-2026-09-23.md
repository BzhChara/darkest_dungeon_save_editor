# 露营技能、Effect 与招募事件读取完整性修复（2026-09-23）

本轮按用户确认修复 [第三十八轮审核](historical-rule-audit-38-2026-09-23.md) 的三项问题，基线为 `599db5006ae703a2b86936946733121d3170212c`。保留原审核报告与失败样本，在新工件目录 `workspaces/hero-supporting-read-fix-20260923/` 中复制原探针并验证；没有操作真实档案、已安装 Mod 或游戏进程，也未提交本轮更改。

## 修改

1. **露营技能池完整性。** `HeroClassCatalog` 复用 `OrderedDefinitionReadState`，完整解析每个有效文件后再发布技能，保留首条分类；新增人物目录字段 `CampingSkillsComplete` 表达是否能确认全部技能及职业适用范围。有效文件读取失败或无法确认文件顺序时，`BuildUpgradePurchases` 拒绝不完整计划。即使人物要求装备 0 个露营技能，编辑器仍要解锁全部适用技能，因此不能略过这个校验。完整可读时的技能不足少取、职业与共享池分别抽取规则保持原样。
2. **Effect 疾病字段。** 有效文件失败使此前赋值变为不确定。后续明确 `.disease` 赋值可以重新确定该 Effect 的字段，显式空字符串可以清空；仅省略字段不能恢复旧线索。未确认值不进入人物运行时怪癖线索。正常读取的逐字段继承、技能 Effect 引用及初始怪癖 HP 规则未改。
3. **招募事件首条结果。** 完整读取的首事件占位，包括空招募结果。文件失败后才出现的 ID 不再作为已确认的首事件结果，故不会误采用后条招募人数；失败前已确认的结果仍保留。这是人物目录与搜索线索，不是重做游戏事件执行器。

`HeroClassCatalog.HeroDefinitions.cs`、`Models.cs` 将完整性带入人物定义；现有目录哈希、预检和提交重读自然观察该字段。没有新增存档字段、旧格式迁移或单独保存保护分支。`MainWindow.RowModels.cs` 对不完整露营池显示“露营技能读取不完整”，生成可用性继续来自同一候选生成器。
