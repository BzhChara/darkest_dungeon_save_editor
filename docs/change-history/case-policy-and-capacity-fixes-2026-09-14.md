# 容量旧保护与资源大小写集中修复（2026-09-14）

用户确认修复[第二十三轮审核](capacity-and-bridge-identity-audit-2026-09-14.md)的两项问题，并要求集中检查大小写处理。实现基于 `5c8fba618648666ef30b120603b5e2ee5c80372c`，不提交本轮新差异，不操作真实档案、活动 Mod 或 Steam 设置。测试使用 `workspaces/contract_tests/` 下的隔离游戏、Mod 和二进制 DSON 档案。

## 修改及影响

1. **容量有效前缀。** `InventorySystemConfigCatalog.cs` 删除遇到任意 NUL 就整份禁用的旧保护，交给共用原生文本读取器在第一个 NUL 停止。前面已赋值的容量和后续独立文件的有效赋值继续生效。文件指纹仍取完整字节；最终非法容量、文件不可读、来源顺序不确定等保护保留。影响副本背包堆叠分配和小镇饰品数量预检，不改变小镇 estate 资源数量算法。
2. **Bridge 地区身份和文件分配。** `BattleEncounterCatalog.RuntimeOrder.cs`、Bridge 主服务、维护与分类文件按精确地区 ID 和难度定位表。`cove`、`Cove`、`COVE` 分开计算、验证及维护。若专用文件的 Windows 路径重合，给新表分配 `ddse_managed_1`、`ddse_managed_2` 等不同文件名，保留必需的地区和难度后缀，并在现有 manifest 的 `RelativeMashPath` 记录它。数字只区分文件名，战斗编号仍按实际表计算。再次进入同地区复用已分配路径；不移动已有文件，不迁移旧版包，不增加清单缺失回退。
3. **人物身份。** `HeroClassCatalog.cs` 与内部模型修正职业目录、info/art 覆盖分组和初始怪癖排斥集合的忽略大小写比较。两个合法职业 `selection`／`Selection` 可以分别取得各自 HP、技能和生成身份；`ban`／`Ban` 不再在排斥元数据中合并。编辑器手动指定怪癖继续沿用控制台式规则，不因本轮而开始执行职业自然生成排斥表。
4. **地图操作链。** 地图读取、写入、区域一致性保护及 App 地图命令使用精确的地区、区域和格子 ID。选中 `rooC/tile0` 不会借用 `ROOC/Tile0`，删除不会顺带修改大小写不同的兄弟节点。游戏档案和 raid 的地区名必须一致。`none` 按精确无副本哨兵处理。人物运行时怪癖摘要及 HP 条件显示也不再折叠语义 ID。
5. **普通房间道具的特殊地区。** `BattleRoomAttachmentCatalog.cs` 仅排除原生字面量 `arena`；自定义 `ARENA` 可按自身请求加载道具池。此修改有下面的原生比较器证据，不是因为其他 ID 区分大小写就推断所有字符串一样。
6. **同一清单的不同请求。** 独立审查指出，同一 Mod 的大小写别名仍在枚举时丢失。修正人物、战斗、物品、容量、饰品、道具和引用的清单集合，并让 `NativeContentFileResolver` 调用共用合并时保留精确路径；否则下一层仍会再次合并同一来源的两个请求。两个清单键即使打开同一个 Windows 文件，也可产生不同查询或原生结果槽。仅对这种同一清单的已知排序不再给出跨提供者大小写竞争的警告；不同提供者的既有不确定性保护保留。

修改覆盖目录读取、UI 选择/显示、保存预检、真实 DSON 提交、Bridge 追加/重用、删除和自动维护。现有 Mod 准入、查询参数、各资源重复 ID 的 first/last/字段更新语义、怪癖进化、战斗占号和原生战斗所有权策略均保留。

## 集中审查的比较边界

首次检索 Core/App 中忽略大小写比较、字符串大小写变换和正则选项，共有 647 处匹配行，再按用途追踪调用。没有全局替换：

| 用途 | 处理 |
| --- | --- |
| 物品、饰品、职业、怪癖、技能、Buff、Effect、怪物、地区等已支持身份 | 保留原始大小写和各消费者的字节限制/哈希冲突保护；修正发现后又被合并的职业、Bridge 等后续入口 |
| Mod 清单目录和构造的资源请求 | 保留既有精确匹配；不会因为 Windows 能打开就放宽清单准入 |
| 原生枚举、文件槽与查询正则 | 继续各消费者已验证的规则，不改成统一的文件名比较 |
| Windows 物理文件、目录、锁、备份和 Profile 路径 | 保留操作系统路径身份；Bridge 单独处理其与资源身份不一致时的冲突 |
| UI 搜索、显示排序、十六进制哈希 | 合理的忽略大小写操作保留；摘要去重不能借此合并不同语义 ID |
| 内部 SourceId、Mod 标题映射、语言别名、启发式显示类型 | 保留既有独立规则；不宣称每一项都已有原生大小写证据 |

本轮把已确认的共同根因沿使用链集中修正，并加入成对身份的行为测试；这不代表已经验证全部游戏 AI、脚本或未来版本的字符串语义。布尔值等原生解析有自己的允许拼写集合，亦不能用一个全局比较器代替。现行查阅入口为[大小写规则](../content-save-rules.md#28-case-handling-follows-the-identity-being-compared)。
