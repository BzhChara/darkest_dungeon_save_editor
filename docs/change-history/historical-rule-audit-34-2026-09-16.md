## P2：掉落引用没有采用游戏实际读取后的身份

代码位置：

- `QuantityItemReferenceAnalyzer.LootParsing.cs:71–92`：以未经原生字符串处理的 `type` 判断 `item/table`，再直接传入 `data.type/data.id`。
- `QuantityItemReferenceAnalyzer.InternalModels.cs:58–73`：`Resolve` 使用 `(type,id)` 原始字符串完全相等。

这两个位置没有体现掉落消费者已经确认的处理步骤：

1. 掉落条目类别先按 C 字符串计算哈希，遇到 NUL 字符结束。
2. `ItemEntry` 调用物品 JSON 读取函数，把 `data.type` 和 `data.id` 分别复制到 64 字节缓冲区，最多保留 63 个 UTF-8 字节。
3. 物品定义查找比较读取后的类型哈希和 ID 哈希，而非完整原始字符串。

可复现的简短例子：有效物品定义只有 `(estate, Az)`，掉落表引用 `(estate, BE)`，权重及数量均为 1，且该掉落表由有效奇物引用。`Az` 和 `BE` 的游戏哈希都是 3567；原生查找会找到唯一的 `Az` 定义。当前编辑器没有发现两个定义之间的冲突，因为这里只有一个定义，但引用分析仍用字符串比较，最终将 `Az` 标成 `SuspectedUnused`、`IsHiddenByDefault=true`。

同一个问题也出现在 `"review_item\u0000tail"` 引用正常定义 `review_item`，以及超长引用经 63 字节截断后对应正常定义的情形。被选物品的定义及保存身份本身没有 NUL、超长或哈希歧义，不能用“非法定义保护”解释这些漏读。`item/table` 类别字段的 C 字符串和哈希别名也能造成整条有效引用遗漏。

影响和限制：

- 缺少其他独立有效引用且尚未出现在副本背包中的 Mod 物品，会被误隐藏；显示隐藏条目后仍能选择。
- 合成样本中，正常定义的数量写入、保存身份、`2+2+1` 堆叠分配和输入对象不变均验证通过。写入后该物品会因为“已在存档中”重新显示，但错误引用标签仍在。
- 此处确认的是目录引用分析错误，不是已确认的存档损坏、战斗编号错位或 Bridge 生成失败，也没有证据说明用户当前档案正在遇到这些边界输入。

建议修复消费者读取和引用解析，保留展示、保存使用的真实定义身份。不能简单恢复大小写不敏感匹配，也不能删除身份冲突保护或对所有资源统一截断。其他 JSON 消费者是否共享完全相同的缓冲区和查找函数，需要分别核对，不能仅凭此实验一并改写。

`git blame` 显示读取原始字段并调用 `Resolve` 的分支至少在 `d1d18f6` 时就已存在；`d55a15f` 将比较改成大小写敏感，`c5bb049` 修正权重及表选择，但没有补齐这层身份转换。不能据此回滚这些已验证的修复，或认为最新的 `0047219` 钱包修复造成了这个问题。

## 新版游戏的原生核对

用户说明游戏最近更新。初次尝试使用旧研究脚本时，文件哈希保护因版本变化触发，未继续使用旧地址。随后按**新版程序自身**的字符串引用和 PE 异常目录重新定位相关函数；没有取消旧脚本的校验，也没有修改游戏文件。

- 当前 EXE SHA-256：`d83a6d578d059c8c9a0bd70453da65d85974715a616872c2dfeff1a5c9ab3a49`。
- 旧研究 EXE SHA-256：`35e5a653279992564809ff8406febd5a02a7d6961044781b1296b38a7096f59b`。
- `week_min` 的 RIP 相对引用定位当前掉落表加载函数 `0x1404449F0–0x140445233`；`0x140445000` 起按字节乘 53 累加，至 NUL 结束，然后分派条目类别。
- 当前加载函数中的虚表及 `+8` 槽定位 `ItemEntry::LoadFromJsonValue` 为 `0x140445620–0x140445762`；其首个直接调用定位物品读取函数 `0x1405D2310–0x1405D28C1`。
- 物品读取中 `0x1405D25FA–0x1405D262B` 使用容量 `0x40` 和 `_TRUNCATE`；PE 导入表确认调用为 `strncpy_s`。`0x1405D2670/0x1405D26C0` 对复制后的两个缓冲区算哈希，`0x1405D26F3` 起逐个比较定义的两个哈希。
- 按 `Loot: Rolled ItemEntry` 日志字符串独立定位了当前掉落执行函数，其定义选择同样比较类型和 ID 的哈希。

这些是新版程序的静态证据及编辑器的可执行隔离验证，**没有在新版游戏中实际触发掉落**。本次仅重新核对上述调用链，不代表已重新验证新版游戏的全部资源规则。旧地址变化本身不等于旧语义全部失效。
