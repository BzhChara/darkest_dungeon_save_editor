# 掉落引用权重与同名表选择修复（2026-09-15）

对应 [第二十五轮只读审核](loot-reference-consumer-audit-2026-09-14.md) 的两项已确认问题，在基线 `670e4e4` 上实现。授权范围为修正物品用途识别，不修改真实档案、活动 Mod、Steam 设置或存档格式；不增加旧数据兼容层。

## 实现

- `QuantityItemReferenceAnalyzer.LootParsing.cs`：读取首个 `chances`，按 float32 排除缺失、零、负数及下溢到零的物品／子表引用。无法确认的权重只传递不确定证据。每条表保留完整条件及加载顺序；表身份使用原生的 C 字符串、63 字节缓冲和哈希规则。
- `QuantityItemReferenceAnalyzer.InternalModels.cs` 与新增 `LootTraversal.cs`：由同名表的无条件集合并集改为有序变体。按难度、地区、感染阶段与闭区间周数选择第一份匹配表；空表也消耗其匹配条件。子表继承父表条件，用范围相交和相减判断完整链是否可能成立。已访问范围按表哈希和确定／不确定路径分别记录，保证循环终止且保留新的有效路径。
- `QuantityItemReferenceAnalyzer.cs`：使用新表库及统一的有条件遍历。没有更改文件发现、清单限制、同路径覆盖和其他资源的重复 ID 规则。
- `LootReferenceContractTests.cs`、测试入口及套件：添加专项和全套调用；旧 JSON 消费测试的正常掉落夹具补充 `chances:1`，保持其原来的文件／入口验证目标。
- 当前规则更新在 `docs/content-save-rules.md` 第 4.2 节及 `docs/resource-duplicate-semantics.md` 第 24 节；测试用法更新在测试 README。

例如，先加载通用表 `T → A`，再加载通用表 `T → B`，现在只将 A 视为通过 T 可获得；先加载难度 1 的 A、再加载难度 3 的 B，仍保留两者各自可用的情境。如果第一份通用表为空，也不回退到第二份。难度 1 的父表不能借难度 3 的子表虚构获得路径。

影响的是用途状态、引用说明、默认隐藏列表以及刷新后的这些结果。已有存档物品仍显示，用户显式选择隐藏物品仍可按既有身份、容量与数量规则写入。饰品、战斗 Bridge 零权重、新建／替换／删除、人物生成和事务保护没有新增规则或格式变更。

## 原生依据及验证边界

沿用 Windows x64 build 27890；EXE SHA-256 为 `35e5a653279992564809ff8406febd5a02a7d6961044781b1296b38a7096f59b`。本次重新提取并核验加载、表选择、掉落执行、子表代码读取及整数负零的 6 份片段，记录在 [native-evidence.json](../../workspaces/loot-reference-fix-20260915/native-evidence.json)。关键位置：

- `0x1404433D3–0x1404433DA`：权重转 float32 并跳过非正数；缺失权重在 `0x1404433AF` 跳到下一条。
- `0x14044179A–0x1404418CE`：按哈希追加完整变体；`0x140441960–0x140441A53`：首个条件匹配返回。
- `0x1404430DB`：难度的 UInt32 类型检查；周数也是 UInt32，构造默认上界在 `0x14044171B` 为全 1。
- `0x140443082–0x1404430C1`：表名先复制再哈希；`0x140443D26–0x140443D45`：子表代码使用同样大小的缓冲。
- `0x14043F3E9`：匹配空表后退出该次表处理，不尝试后续变体。
- `0x14024E0F3–0x14024E11B`：整数 `-0` 归为支持 UInt32 的零。`week_max:-0` 不能被 .NET `TryGetUInt32` 拒绝后误留默认最大值；实现用带范围检查的整数读取保留该语义。

这不是一次新的游戏内掉落实验。错类型或正溢出权重的实际随机行为不宣称已完整验证；编辑器保留相应不确定证据。负溢出符合已证实的非正值跳过分支。目录仍分析“在某组情境中可能有用途”，没有实现全部任务／事件触发器、特殊奖励、随机概率或掉落数量模拟。官方物品的原有分类保持不变。
